# 검토 결과 화면: 다음 행동 중심

## 누구의 어떤 문제를 푸는가

화장품 광고를 내보내기 전에 마케팅 담당자와 품질, 인허가 담당자가 상세페이지를 한 줄씩 읽으며
식약처 기준에 걸리는 표현을 찾고, 시험자료와 기능성 보고 내용을 맞춰 보고, 고칠 문구를 정한다.
이 일이 오래 걸리는 이유는 법령 검색이 아니라 "어디부터 보고, 무슨 자료를 요청하고, 어떻게 고칠지"를
사람이 다시 정리해야 하기 때문이다. 결과 화면은 이 정리를 대신한다.

화면은 세 질문에 순서대로 답한다.

1. 무엇부터 봐야 하나: 문구를 다음 행동으로 분류해 건수를 보여 주고, 누르면 그 문구만 남긴다.
2. 어떤 자료가 필요한가: 문구마다 반복되던 자료 요청을 자료 종류별 한 줄로 묶는다.
3. 어떻게 고치나: 검증을 통과한 수정안을 보여 주고, 없으면 왜 없는지 알려 준다.

법령 조문, 규칙 매칭, 공공데이터 조회 기록은 판단 근거다. 카드에서는 "근거 보기"로 접어 둔다.

## 다음 행동 분류

구현은 frontend/src/shared/constants/reviewActions.js 한 곳이다. Agent 결과(rules, checks, severity)만으로
계산하므로 예전에 저장된 결과에도 같은 분류가 적용된다. severity는 검토 순서, 분류는 해야 할 일이다.

| 분류 | 조건 | 담당자 행동 |
| --- | --- | --- |
| 수정 권고 | 의약품 오인, 절대 표현 규칙, 되돌림이나 리프팅 같은 효능 표현, 보고 기능과 다름, 금지 원료, severity high | 수정안 채택 또는 직접 수정 |
| 자료 확인 필요 | 시험자료 미제출, 기능성 효능을 말하는데 보고품목 미확인, 인증이나 심사 표현, 제한 원료, GMP 목록 없음 | 자료 첨부 또는 대조. 자료가 없으면 수정 |
| 분석 보류 | 공식 기록 조회 실패, 법령 검색 실패 | 다시 조회하거나 원본 자료로 직접 확인. 광고의 문제로 보지 않는다 |
| 표현 참고 | 위에 해당하지 않는 일반 효능, 감성 표현 | 표현 수위만 보고 원문 유지 가능. 한 번에 원문 유지로 결정할 수 있다 |

조회되지 않음(not_found)은 미보고를 뜻하지 않는다. 문구가 주름, 미백 같은 기능을 실제로 말할 때만
기능성 보고번호를 자료로 요청한다. 성분 대조의 needs_input은 문구에 성분 이름이 없다는 뜻이라 요청하지 않는다.

## 수정안

수정안은 규칙 검사와 모델 검증을 모두 통과해야 저장된다(docs/03-contracts.md).
원문과 같거나 잘린 문안, 원문의 위험 표현을 남기거나 새 위험 표현을 넣은 문안, 문장을 중간에 끊은 문안은
규칙 검사에서 떨어진다. 자료 확인이 먼저인 문구는 수정안을 "자료가 없을 때 쓸 수 있는 수정안"으로 보여 준다.
작성 중인 직접 수정 문구와 다시쓰기 메모는 저장 전까지 브라우저에 임시 보관한다.

## 제출 증빙 대조

증빙은 광고 파일과 다르게 읽는다(documents.prepare_evidence). 80쪽까지 받고, 글자가 있는 페이지는 그대로 읽고
스캔 페이지만 OCR한다. 읽지 못하면 EVIDENCE_PAGE_LIMIT, FILE_TOO_LARGE, DOCUMENT_FETCH_FAILED, DOCUMENT_PARSE_FAILED처럼
이유를 남긴다. Agent(evidence.py)는 문서마다 시험 요약(종류, 측정 항목, 기간, 대상, 기관, 결과)을 만들고,
실증이 필요한 광고 주장을 한 번에 대조해 뒷받침함, 다른 시험, 조건 다름, 증빙에 없음으로 나눈다.
광고 각주의 시험 조건도 함께 넘기고, OCR 오타로 기관명이 조금 다른 경우는 불일치로 보지 않는다.

예: 투집 포어본드 광고에 피부 일차자극 시험 보고서(30쪽)를 내면 모공 개선 주장은 "다른 시험"으로 나오고
"모공 개선 인체적용시험 보고서"를 추가로 받을 자료로 보여 준다. 연구기관 표기는 "뒷받침함"이다.
대조 결과는 어떤 서류를 더 받아야 하는지 알려 주는 것이지 위반 판정이 아니다.

## 남은 과제

- 같은 구간의 문구, 사진 관찰, 자료 상태를 쟁점 하나로 묶기. 지금은 구간 줄 안에 나란히 둔다.
- 분류를 Agent 결과의 필드로 옮겨 리포트와 API 소비자가 같은 값을 쓰게 하기.
- 수정안을 모든 문구에 미리 만들지 않고, 수정 권고 문구와 요청 시에만 만들어 시간과 비용 줄이기.
- 실제 광고 묶음으로 놓친 쟁점과 불필요한 경고 비율을 재는 평가 세트.
- 증빙 대조 결과를 시험 보고서의 원문 위치(쪽, 표)와 연결하기.
